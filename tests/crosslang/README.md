# Cross-language (MATLAB ↔ Python) regression gate

Keeps the three reconciled MATLAB/Python divergences — low-pass hop-size
derivation, `firwin` centring, Nyquist convention — from silently reappearing.

## What's here

- `run_crosslang_tests.py` — orchestrator. In `--skip-matlab` mode it runs
  `export_python.py` (current cool-frames) and diffs the result, field by field,
  against the committed MATLAB reference in `results/matlab/`.
- `export_python.py` — regenerates the Python reference data. (Imports were
  updated from the old `ltfat_filterbank` package name to `cool-frames`.)
- `results/matlab/*.mat` — the committed MATLAB reference (generated by
  `export_matlab.m` in the original harness at
  `research/tools/testing/crosslang/`; regenerate there with MATLAB/Octave
  when the API intentionally changes).

## Run locally

```bash
pip install -e ".[dev]" scipy
python tests/crosslang/run_crosslang_tests.py --skip-matlab --tol 1e-8
# or via pytest:
COOL_FRAMES_RUN_CROSSLANG=1 pytest tests/crosslang/test_crosslang.py -v
```

## CI

The `crosslang` job in `.github/workflows/ci.yml` runs this on every push/PR.

**It is currently `continue-on-error: true` (non-blocking).** Reason: the
harness and its reference `.mat` files predate the `cool-frames` rename (the
reference was generated 2026-04), so the first runs may flag *staleness*
rather than real regressions. Once it is confirmed green against current cool-frames
(refresh `results/matlab/` from MATLAB/Octave if the API legitimately moved),
flip `continue-on-error` to `false` to make it a hard gate.
